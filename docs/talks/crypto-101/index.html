// FOUNDATIONS 01

What is cryptography?

Cryptography is the science of keeping information safe when other people might be watching it, or trying to change it.

ConfidentialityCan anyone else read it?TOOLS FOR THISEncryption (AES, RSA)
IntegrityWas it changed on the way?TOOLS FOR THISHashing (SHA-256) and tamper checks (GCM)
AuthenticationWho am I really talking to?TOOLS FOR THISPasswords, certificates, signatures
Non-repudiationCan the sender deny sending it?TOOLS FOR THISDigital signatures

You use all four every day: messaging, online banking, logging in, and every https:// page.

~3 min

  • SayCryptography keeps information safe when other people might be watching it, or trying to change it.
  • SayThe four goals in plain words: confidentiality = secret, integrity = unchanged, authentication = who, non-repudiation = can't deny it later.
  • AskWhich of these does a banking app need? Answer: All four.
  • Next"Let's start with the oldest trick in the book."

// FOUNDATIONS 02

Your first cipher: the Caesar shift

Plain alphabet / cipher alphabet: every letter shifted forward by the key

Try itTo encrypt, replace each letter with the one 3 places later: H becomes K, E becomes H. To decrypt, shift back by 3. The key is just the number 3.
Why it is weakThere are only 25 possible keys, so a computer tries them all in an instant. Letter counts also give it away: the most common letter is probably E.
What modern ciphers fixA huge number of keys, so guessing is hopeless. Heavy scrambling that hides letter patterns. And the method can be public: only the key is secret.

~2 min

  • SayShift every letter forward by the key. With key 3, HELLO becomes KHOOR.
  • ShowDrag the key slider. The pink cells in the alphabet strip show which letter becomes which.
  • AskDecrypt KHOOR in your head. Answer: Shift each letter back 3: HELLO.
  • SayThe key is one number from 1 to 25. That's the weakness.
  • Next"How would you crack it?"

      // HASHING 01
      How hashing works
      
  
      
    
      
      
      
        
      Deterministic and fastSame input always gives the same hash. Quick to compute.
      
        
      Fixed-size outputA single letter or a whole movie both give 256 bits.
      
        
      Avalanche effectChange one input bit and about half the output bits change.
      
        
      One-wayGiven a hash, the only way to find the input is to guess.
      
        
      No twinsIt should be practically impossible to find two inputs with the same hash.
      
      
      
      
      How MD5, SHA-1 and SHA-2 process a message: pad it, cut it into blocks, mix each block into a running result
        
      IVf ← M1f ← M2f ← M3hash
      
    
      
    
      
      
      Avalanche, live

      • ShowDrag the slider to flip other bits. It's always about half.

      // HASHING 03
      Known issues: MD5 and SHA-1 are broken
      
  
      
    
        
      
      1. 1995SHA-1 becomes a US standard
        2. 
      
      2. 2004Researchers find two inputs with the same MD5 hash
        3. 
      
      3. 2008Fake website certificate made using the MD5 weakness
        4. 
      
      4. 2012Flame malware fakes a trusted software signature (MD5)
        5. 
      
      5. 2017SHAttered: first SHA-1 collision, found by Google
        6. 
      
      6. 2020Faster SHA-1 attack: "SHA-1 is a Shambles"
        7. 
    
      
    
      
      
      MD5 (128-bit)Two different inputs can be made to match in seconds. Cannot be trusted for signatures or certificates. A graphics card tries billions per second, so it is useless for passwords.
      
      
      SHA-1 (160-bit)Attacks have made it much cheaper to break. Two different PDFs with the same SHA-1 hash were published in 2017. Browsers and certificate authorities have dropped it.
      
      
      Use insteadSHA-256, SHA-384 or SHA-512 (the SHA-2 family). SHA-3 (a newer, different design). BLAKE2 / BLAKE3 for speed. For passwords: Argon2id, bcrypt, scrypt.
      
    
      
  
      
  
      ~2 min
      • Say"Broken" means attackers can make two inputs with the same hash on purpose.
      • SayWalk the timeline: MD5 collisions in 2004, a fake certificate in 2008, the Flame malware in 2012, the first SHA-1 collision in 2017.
      • SayFor new work use SHA-256, SHA-3 or BLAKE2. For passwords use Argon2id or bcrypt.

      // HASHING 04
      Salt and pepper
      
  
      
    
      
      
      
    
      
    
      
      
      No salt
      
      
      Salt random, unique, stored beside the hash
      
      
      Pepper secret, shared, kept outside the database
      
    
      
    
      Salt defeats rainbow tables (huge lists of pre-computed hashes) and is not secret. Pepper lives in a vault, is hard to change later (track which version was used), and is mixed in before hashing.
      
  
      
  
      ~3 min
      • SayAlice and Bob both pick the password "sunshine".
      • ShowLeft, no salt: identical hashes, and the attacker's pre-computed table cracks it instantly.
      • ShowMiddle, a random salt per user stored beside the hash: different hashes, the table is useless, and each user must be cracked separately.
      • ShowRight, a pepper: one secret for the whole app, kept outside the database. Steal only the database and you can't even test a guess.
      • AskWhy is it fine to store the salt in the database? Answer: It isn't secret; it only forces attackers to work on each user separately.

        // ENCRYPTION 02
        Symmetric vs asymmetric encryption
        
  
        
    
        
      
        SYMMETRIC · one shared key
        Alice KciphertextBob K
        Alice and Bob hold the same secret key K. Fast, but how do they share K safely in the first place?
        
      
        ASYMMETRIC · a key pair
        Alice Bob's publicciphertextBob private
        Encrypt with Bob's public key, decrypt with his private key. Slower, but no secret has to be shared beforehand.
        
    
        
    
        
      
        SymmetricAsymmetric
        
      
        
        SpeedVery fast (built into modern chips)Much slower (about 100 to 1000 times)
        
        
        Key sharingMust share the key secretly firstPublic key can be shared openly

        AlgorithmsAES, ChaCha20RSA, ECC, ML-KEM

        • SayAsymmetric: a key pair. Anyone can lock with Bob's public key; only Bob's private key unlocks it. Slower, but nothing secret to share up front.

        // ENCRYPTION 03
        AES: the standard symmetric cipher

        12rounds · AES-192
        14rounds · AES-256

        // ENCRYPTION 06
        Known issues with certain AES modes
        
  
        
    
        ECB: patterns survive
        Identical blocks of the original data become identical blocks of encrypted data, so the shape of an image still shows through.
        Fix: never use ECB.
        
    
        CBC: padding leaks
        If a server reveals whether the padding (filler bytes) was valid, an attacker can decrypt the message bit by bit (POODLE, Lucky13). Predictable IVs allowed the BEAST attack.
        Fix: use authenticated encryption (like GCM), or add a tamper check.
        
    
        CTR: nonce reuse
        Reusing a nonce (a number meant to be used once) repeats the scrambled stream, so attackers can combine two messages and cancel it out. Tampering also goes unnoticed.
        Fix: never repeat a nonce; add a tamper check.
        
    
        GCM: never reuse a nonce
        Repeating a nonce leaks the secret behind the tamper check, so attackers can forge messages. Random nonces can collide after about 4 billion messages.
        Fix: use counters for nonces, change keys often, or use AES-GCM-SIV.
        
  
        
  
        ~3 min
        • SayEach mode has a classic mistake.
        • SayECB: patterns survive. The next slide shows it.
        • SayCBC: if a server reveals whether the padding was valid, attackers can work out the message (POODLE, Lucky13).
        • SayCTR and GCM: never reuse a nonce. It repeats the stream, and in GCM it also lets attackers forge messages.
        • SayThe fix almost every time: authenticated encryption like AES-GCM, with a counter as the nonce.

              // WRAP-UP
              Key takeaways
              
  
              
    
              Hash is not encryptA hash is a one-way fingerprint. Encryption is reversible with the key.
              
    
              Store passwords properlyDrop MD5 and SHA-1. Use Argon2id or bcrypt with a unique salt, plus a pepper.
              
    
              Use AES-256-GCMIt detects tampering. Never use ECB, and never reuse a nonce.
              
    
              Asymmetric for keysUse RSA (2048+ bits, with padding) or ECC to share keys and sign.
              
    
              Built on hard puzzlesRSA, ECC and post-quantum schemes each rest on a puzzle that is easy one way and hopeless to reverse.
              
    
              Plan for quantumList where you use crypto, be ready to swap it, try hybrid ML-KEM, and prefer AES-256.
              
  
              
  
              ~2 min
              • SayRead the six cards quickly.
              • AskHave each table name the one takeaway they'll remember. Answer: Any of the six.

              // APPENDIX
              Glossary
              
  
              
    
              
      
              Plaintext / ciphertext
              The readable message, and its scrambled form.
              
      
              Key
              The secret that locks and unlocks. Longer means harder to guess.
              
      
              Cipher
              The recipe for encrypting (AES, RSA). It can be public.
              
      
              Encoding
              Bytes written another way, like hex or Base64. No key: anyone can reverse it.
              
      
              Hash
              A fixed-size, one-way fingerprint of any data (SHA-256).
              
      
              Salt
              A random value per password, so equal passwords hash differently.
              
      
              Pepper
              One secret mixed into every password hash, kept outside the database.
              
      
              Nonce
              A number used once per message. Never repeat it with the same key.
              
      
              IV
              Initialisation vector: a random starting value, as in CBC mode.
              
      
              Mode of operation
              How a block cipher handles long messages: ECB, CBC, CTR, GCM.
              
      
              Tag (MAC)
              A short checksum made with the key. It fails if the message changes.
              
      
              Authenticated encryption
              Encryption plus a built-in tamper check, like AES-GCM.
              
      
              Public / private key
              A key pair. Share the public one; the private one never leaves you.
              
      
              Key exchange
              Agreeing on a shared secret over a public channel (ECDH).
              
      
              Digital signature
              Made with a private key; anyone can check it with the public key.
              
      
              Passkey
              A per-site key pair that replaces a password. You log in by signing.
              
      
              Certificate
              A public key plus a name, signed by a certificate authority.
              
      
              Certificate authority
              An organisation your browser trusts to vouch for websites.
              
      
              End-to-end encryption
              Only the people talking hold the keys; the server sees ciphertext.
              
      
              Safety number
              A code both people compare to check nobody swapped their keys.
              
      
              CSPRNG
              A secure random number generator: output nobody can predict.
              
      
              Seed
              A generator's starting value. Guess the seed and you know its output.
              
      
              Collision
              Two different inputs that give the same hash.
              
      
              Brute force
              Trying every possible key or password until one works.
              
      
              Post-quantum
              Built to resist quantum computers, like ML-KEM and ML-DSA.
